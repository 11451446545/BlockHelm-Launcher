# 26A17092：从旧版 91 在启动器内更新

## 协议与版本

旧版 `v26A17091` 只接受 schemaVersion 1、单个 Windows x64 EXE 资产，
要求清单版本名计算得到的 versionCode 与声明一致且大于本机版本。
维护补丁使用 `26A17092` / `648114322`，两版主程序分别显示
`26A17092` 和 `26A17092-Compatible`；安装后不会重复提示同一补丁。

发布标签为 `v26A17092-patch`，指向本次源码提交。
标签的 `-patch` 后缀使旧 release workflow 跳过，避免它重新构建单一框架资产或覆盖更新清单。
正式版更新清单最后才切换，测试版频道保持独立。

## 更新程序

`Launcher.UpdateBootstrap` 是自包含 .NET 6 x64 更新程序，接受旧版的
`--apply-update --pid --source --target --log-dir --restart` 参数。
它内含现代版 .NET 8 和兼容版 .NET 6 主程序；Windows 6.1–6.3 选择兼容版，
Windows 10 及更新版本选择现代版。

提取目标主程序前校验内嵌元数据，提取过程中验证完整长度与 SHA-256。
临时文件只写入更新缓存的新建子目录，不改游戏、账户或设置。
替换、备份、重启确认、超时回滚直接编译复用
`LauncherUpdateApplyRunner.cs` / `LauncherUpdateStartupCoordinator.cs`，没有第二套替换算法。
事务保存的 updater 路径指向所选主程序，它仍支持 `--recover-update`。

此包是完整 EXE 更新，不是二进制差分；包含双运行库，因此体积大于单版主程序。
它不是安装器，不写卸载信息、快捷方式或系统前置包。
Win7 用户须已经安装并能正常启动兼容版 91；新机器继续使用统一安装器。
原版的外部服务配置规则不变，缺少服务配置不由此补丁解决。

## 构建与验证

在该提交使用 PowerShell 7 和 .NET SDK 8：

```powershell
dotnet test Launcher.sln -c Release
dotnet test Launcher.CompatibilityTests/Launcher.CompatibilityTests.csproj -c Release
./build/package-92-update.ps1
./build/test-92-update.ps1
```

打包先发布两版主程序，生成内嵌哈希清单，再发布更新程序；
输出至桌面 `26A17092更新补丁`，包括更新 EXE、SHA-256 文件和待发布的 `latest.json`。
不覆盖桌面已发布的 91 统一安装器。
重现旧安装器应检出 `v26A17091-universal`，其构建说明为当次发布的历史记录。

合同验证脚本从 `v26A17091` 提取原始更新检查、下载及 URL/哈希校验源码，
仅调整命名空间以与现有代码并存。测试使用真实原版 91 EXE 作待替换目标，
用隔离 HTTP 响应传送本地最终更新包，再真正启动该更新包并验证替换及启动确认。
测试目录位于 `.tmp`，账户与运行库解压目录隔离，真实用户数据不参与测试。
只验证目标目录下的测试进程，不终止用户正在运行的其他启动器。

发布资产并核对 GitHub SHA-256 后，才更新 `update-manifests` 分支的
`update/release/latest.json`。发布后运行：

```powershell
./build/test-92-update.ps1 -CheckLive
```

Win7 实机上的驱动、Aero、登录、联机和完整游戏启动仍未验收；
在现代系统运行 .NET 6 测试不等同于 Win7 实机测试。
